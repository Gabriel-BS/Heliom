# 🧬 Heliom

<img src="./docs/statics/heliom-logo.png" alt="Heliom Logo" max-height="200px" width="auto" />

**The DNA of modern software delivery.**  
Heliom is a secure, stack-based internal developer platform that empowers developers and platform engineers to collaborate, deploy, and manage infrastructure at scale.


---

## ✨ What is Heliom?

Heliom is a developer-first platform that unifies applications, infrastructure, and environments into a single, composable system.

Built on:
- ✅ **Zitadel** for identity, roles, and secure access
- 🧱 **Stacks** for versioned app and infra management
- 🌍 **Environments** for isolated, on-demand deployment contexts
- 🛠️ **Backstage** for a fully integrated self-service UI
- 🔁 **GitOps & CI/CD** native workflows

---

## 🚀 Key Features

- 🔐 **Authentication & Authorization** with enterprise-grade SSO + RBAC
- 🧩 **Stack-based architecture**: monorepos or single services, infra or apps
- 🌱 **Self-service environments**: staging, production, client-specific, or preview per PR
- 📦 **Resource-aware access**: DBs, buckets, and topics defined and scoped declaratively
- ✅ **Approval workflows**: protect deletes, promotions, and critical actions
- 📊 **Observability-ready**: metrics, dashboards, and logs per stack

---

## 📦 Stack Philosophy

A **stack** is the atomic unit of Heliom — a versioned, deployable unit composed of one or more applications or infrastructure components.  
Stacks live in Git, are managed through environments, and respect access rules defined at the platform level.
